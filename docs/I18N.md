# Traducciones

La interfaz usa el sistema de traducción de Slint con archivos gettext (`.po`). Las traducciones se incrustan en el binario al compilar, así que no hay que instalar archivos aparte.

## Cómo se escribe un texto

En cualquier `.slint`, todo texto visible va en inglés dentro de `@tr()`:

```slint
Text { text: @tr("Maximum level"); }
Text { text: @tr("{} / {} XP to next level", xp, needed); }
```

El motor de lógica nunca devuelve textos. Si un valor del motor necesita nombre (un rango, una categoría), se traduce en `ui/theme/labels.slint`.

## Flujo

1. Escribes o cambias textos en los `.slint`.
2. Ejecutas `tools/i18n.sh`. El script extrae los textos a `i18n/mog-ui.pot`, actualiza el `.po` de cada idioma y lista lo que falta traducir.
3. Rellenas lo que falta. Para no completarlas una por una, `tools/po_fill.py` toma un JSON `{"texto en inglés": "traducción"}` y completa solo las entradas vacías. Para textos con plural (`@tr("{n} week" | "{n} weeks" % n)`) la traducción es una lista con una forma por plural: `{"{n} week": ["{n} semana", "{n} semanas"]}`.
4. `tools/i18n.sh --check` falla si queda algo sin traducir. CI lo ejecuta en cada cambio, así que una versión no puede salir con textos a medias.

El inglés es el idioma fuente: su `.po` se rellena solo.

Si existe `i18n/<idioma>/fill.json`, `tools/i18n.sh` lo aplica en cada corrida. Hoy lo usa el catálogo de ejercicios: `tools/gen_exercises.py` escribe `i18n/es/fill.json` con el nombre en español de cada ejercicio, sacado del CSV.

## Agregar un idioma

1. Crea `i18n/<código>/LC_MESSAGES/` (por ejemplo `i18n/pt/LC_MESSAGES/`).
2. Ejecuta `tools/i18n.sh`: crea el `.po` vacío.
3. Rellénalo con `tools/po_fill.py`.
4. Agrega el código a `LANGUAGES` en `crates/mog-app/src/main.rs` y un botón en el selector.

## Requisitos

- `cargo install slint-tr-extractor`
- gettext (`msgmerge`, `msginit`, `msgen`, `msgattrib`)
